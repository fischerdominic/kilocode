# Tool System

Tools are functions the AI agent can call to interact with the filesystem, execute commands, fetch data, and use external services via MCP.

## Tool Architecture

Every tool follows a consistent interface:

```typescript
interface ToolDefinition {
  // Tool identity
  id: string                    // Unique tool identifier
  
  // Description shown to the LLM
  description: string
  
  // JSON Schema for the tool's arguments
  parameters: JSONSchema
  
  // Execution function
  execute: (args: ToolArgs, context: ToolContext) => Promise<ToolResult>
}

interface ToolContext {
  sessionID: string             // Current session
  agent: string                 // Current agent
  directory: string             // Workspace directory
  worktree: string              // Worktree directory (if any)
  ask: (request: PermissionRequest) => Promise<PermissionReply>
  write: (path: string, content: string) => Promise<void>
  read: (path: string) => Promise<string>
}

interface ToolResult {
  output: string                // Result text shown to the LLM
  title?: string                // Optional title for UI display
  metadata?: Record<string, any>
  attachments?: FileAttachment[] // Files generated by the tool
}
```

## Built-in Tools

### File Operations

#### `read` — Read File Contents

Reads the contents of a file.

```json
{
  "id": "read",
  "description": "Read the contents of a file at the given path.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "description": "Absolute path to the file" }
    },
    "required": ["path"]
  }
}
```

**Permission:** `read`
**Behavior:** Returns file contents as text. Binary files are skipped with a warning.

#### `write` — Write File Contents

Overwrites a file with new content.

```json
{
  "id": "write",
  "description": "Write content to a file, creating it if it doesn't exist.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "description": "Absolute path to the file" },
      "content": { "type": "string", "description": "Content to write" }
    },
    "required": ["path", "content"]
  }
}
```

**Permission:** `write`
**Behavior:** Creates parent directories if needed. Overwrites existing content.

#### `edit` — Apply Diff-Based Edits

Applies targeted edits to a file using unified diff format.

```json
{
  "id": "edit",
  "description": "Apply precise edits to a file using unified diff format.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "description": "Absolute path to the file" },
      "diff": { "type": "string", "description": "Unified diff to apply" }
    },
    "required": ["path", "diff"]
  }
}
```

**Permission:** `edit`
**Behavior:** Applies the diff to the file. More precise than write for small changes.

#### `apply_patch` — Apply Unified Diff Patch

Applies a full unified diff patch, potentially across multiple files.

**Permission:** `patch`

### Shell

#### `bash` — Execute Shell Command

Runs a command in the user's configured shell (via VS Code terminal).

```json
{

  "parameters": {

**Permission:** `bash`

### Task Management

Spawns a subagent to handle a specific task in parallel.

{

}
```

**Permission:** `task`
**Constraint:** Only available if the agent's permission allows `task`

### MCP Tools

Tools provided by connected MCP servers are dynamically registered and appear alongside built-in tools.

**Naming Convention:** `mcp_<server-name>_<tool-name>`

Example: If the `playwright` MCP server provides a `browser_navigate` tool, it appears as `mcp_playwright_browser_navigate`.

**Permission:** `mcp_<server-name>` (e.g., `mcp_playwright`)

## Tool Registry

The tool registry filters and presents available tools based on the current agent's permissions.

```typescript
class ToolRegistry {
  // All registered tools
  private builtin: ToolDefinition[]
  private mcp: ToolDefinition[]
  private custom: ToolDefinition[]
  
  // Get tools available for the current agent
  getToolsForAgent(agent: AgentDefinition, permission?: PermissionRuleset): ToolDefinition[] {
    return [...this.builtin, ...this.mcp, ...this.custom].filter(tool => {
      // Check if the agent has permission for this tool
      const permKey = this.getPermissionKey(tool.id)
      const rule = Permission.evaluate(permKey, "*", agent.permission, permission)
      return rule.action !== "deny"
    })
  }
  
  // Get the permission key for a tool
  private getPermissionKey(toolId: string): string {
    if (toolId.startsWith("mcp_")) return toolId  // MCP tools use server name
    const editTools = ["write", "edit", "apply_patch"]
    if (editTools.includes(toolId)) return "edit"
    return toolId
  }
}
```

## Tool Execution Flow

```
1. LLM decides to call a tool
        │
        ▼
2. Tool registry validates arguments against JSON Schema
        │
        ▼
3. Permission engine evaluates the tool call
   ├── Denied → Return error to LLM
   ├── Ask → Wait for user approval
   └── Allowed → Continue
        │
        ▼
4. Execute the tool with the provided arguments
        │
        ▼
5. Capture output (stdout, return value, etc.)
        │
        ▼
6. Truncate output if too long (token limit)
        │
        ▼
7. Return result to LLM as tool response
        │
        ▼
8. LLM continues generation with the result
```

## Tool Output Truncation

Long tool outputs are truncated to fit within the model's context window:

```typescript
function truncateOutput(output: string, maxTokens: number): TruncatedOutput {
  const tokenCount = countTokens(output)
  if (tokenCount <= maxTokens) return { content: output, truncated: false }
  
  // Keep the beginning and end, truncate the middle
  const begin = takeTokens(output, maxTokens / 3)
  const end = takeTokensLast(output, maxTokens / 3)
  return {
    content: `${begin}\n\n... [truncated ${tokenCount - maxTokens} tokens] ...\n\n${end}`,
    truncated: true,
  }
}
```

## Custom Tool Plugins (Optional Extension)

Users can write custom tools as TypeScript files:

```typescript
// my-tools.ts
export const myTool = {
  id: "my_tool",
  description: "Do something custom",
  args: z.object({
    input: z.string(),
  }),
  execute: async (args: { input: string }) => {
    const result = await doSomething(args.input)
    return { output: result }
  },
}
```

Place in `<config-dir>/tool/*.ts` and the backend auto-discovers and registers them.
